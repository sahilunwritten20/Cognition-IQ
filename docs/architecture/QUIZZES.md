# Quizzes (Step 5)

A quiz is a teacher's list of their OWN questions, a schedule, and a set of class+divisions allowed to sit it.
Questions are copied into each student's attempt at start (Steps 7-8), so editing a question or a quiz never changes an
attempt in progress or finished.

## Stored status and derived state
| Stored `status` | Meaning |
|---|---|
| `draft` | being built; editable; invisible to students |
| `published` | open to eligible students according to the window |
| `paused` | blocks NEW starts only (running attempts keep their deadlines) |
| `closed` | final: no new starts |

`state` (derived from status + clock, never stored): `draft | scheduled | live | ended | paused | closed`.
The window is **[startAt, endAt)**: open exactly at `startAt`, closed exactly at `endAt`. One function,
`evaluateAvailability`, is the only place this rule lives; the exam-start endpoint (Step 7) must call it.

## Transitions (all by the owning teacher, all audited; reason mandatory where shown)
`draft -> published` (publish validation) - `published -> paused` (reason) - `paused -> published` (resume) -
`draft|published|paused -> closed` (reason) - `published|paused -> draft` (unpublish, reason; **refused once any student
has started**).

## What the server owns (a client that sends any of these gets a 400)
`totalMarks` (sum of per-quiz marks, rounded half-up to 2 decimals, D-04), `status`, `departmentId`, `academicYearId`
(derived from the teacher's active teaching assignments), `createdBy`, the code hash, `resultsPublishedAt`.
Dates must be ISO 8601 **with an offset** and are stored in UTC.

## Scope rules
- A teacher can target only class+divisions they are **currently assigned** to for the quiz's subject (unassigned or
  non-existent: 403), all within one academic year. The subject cannot be changed after creation.
- Only the teacher's own, active questions of that subject can be added (private bank, D-13). At publish time the
  questions and assignments are checked AGAIN (an archived question or a revoked assignment blocks publishing).
- Teacher: own quizzes only (someone else's: 404). HOD: read-only, own department. SUPER_ADMIN: read-only.
  Student: only `GET /student/quizzes`.

## Publish validation (all problems are returned together)
at least 1 question - total marks > 0 - start and end set, end after start and not already past - duration set and not longer
than the window - every target still assigned - every question still active and yours.

## Access code
Generated by the server (8 characters, no look-alikes, shown as `ABCD-EFGH`), stored only as an HMAC with its own sub-key,
returned **once** (when created, when the mode first needs one, or when regenerated) and never retrievable.
Regenerating invalidates the old code immediately. A code is an ADDITIONAL condition: it never bypasses login, enrollment,
schedule, status, attempt limit or eligibility. Verification is constant-time (`verifyQuizCode`, used at start in Step 7).

## Student view (`GET /student/quizzes`)
Published or paused quizzes for the student's own enrollment (class+division in the quiz's year), each with `available` and a
readable reason (`not_started`, `ended`, `paused`, `no_attempts_left`...). Never listed: drafts, closed quizzes, quizzes that ended
over 24 hours ago, other classes' quizzes. The DTO is an explicit allow-list (no question ids, code, teacher or department ids).

## Hooks left for later steps
- `AttemptLookup` (counts finished attempts; says whether any attempt exists): returns "none" until Step 7 supplies the real one.
- Result publication (`resultsPublishedAt`, `resultVisibility`) is stored and shown; the publish-results action arrives with grading (Step 9).
- Pausing/closing does not finalize running attempts; emergency close and extend are part of the live monitor (Step 10).
